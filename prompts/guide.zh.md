## teaching-understanding
实时讲授理解接管的是“这次证据改变了什么”。primary 一次问 operation、各来源 stance、relationEvidence；这些问题共享状态，不能假设它们互相读到了答案。只有获得关系意图及资格后才构造 relation follow-up，判断关系端点与类型。
理由：同一主题可包含多个教学对象；同一对象的补条件应保持身份。再次提及不必创造新版本。Host 生成候选和来源权限，模型不能选择不存在的选项，故权限过滤成功不是模型理解学生权限的证据。
正例：A 已是 X，补“仅当 Y”通常修订 A。反例：同一文学主题下，一个独立例子可成为新 Cue，不应按主题强合并。原问题应保持 question，被批评的例子不能升级为 asserted。
现有 22 个 authored 场景保留原 case ID、motivation 和断言，包括有明显提示词的工程回归。它们不是 22 条真实成功记录，也不是盲测。compound-development 无语义断言，保持 UNSCORED。全链路调度、续接、异步和竞争由运行期测试负责。
审查时先看 sources、criteria 与 coverage，再看答案和接受结果。记录候选缺失、上下文缺失、模型误判与 Host rejection，不能把失败折算成 NO_CHANGE。
最近变化：#20 静态措辞原样抽取；本轮补齐阅读、来源用途与版本证据，不调整现有判断原则。

## accepted-expression
Presentation 判断“怎样更清楚地表达已经选定的同一内容”。sourceText 是唯一正文依据；referenceContext 仅消歧，不得引入新教学点。它不补答问题、不纠正教师、不借背景补出公式。
理由：派生呈现不应改变课堂语义。数字／单位、否定、限定条件、不确定性、比较方向、问题与例子角色必须保留；双语不是识别失败。显式顺序不能升级为因果，关系使用最弱的忠实形式。
正例：“只有 Y 才适用”保留条件地整理。反例：删去“只有”、把“可能”变“确定”、把“先后”画成 causes。返回 source 可以安全，但没有证明帮助阅读；改善效用仍需人审。
当前调度只接受 current Cue，且选定文本须由完整 Final 原样重建。离开 Display 不代表语义失效，但旧调度仍限制 current。子范围不能满足 whole-Final 时，是输入覆盖限制，不是模型输出失败。新评测通过同一 presentationInput 与 HTTP validator 构造请求；不声称模拟异步显示整条链路。
评测逐行给出人工审查焦点和成对反例。所有成功解析行也为 UNSCORED，不以包含关键词或 schema 通过代替忠实性。模型运行与人工效用判断本轮均 NOT_RUN。
最近变化：抽取前先保存实际 HTTP 请求快照，再共享 builder、validator、schema 和 parser；保留旧 student reading / note-taking 措辞及所有模型参数。更改这些语义需独立意图说明。

## multi-cue-expression
组合表达把已接受的 A/B 放在一起便于比较或回顾，不将它们变成一个 canonical Cue。输入须明确所有选定内容、Cue 版本和实际依赖关系。
正例：按已记录差异制作独立对比表达，保持两个身份。反例：因为两者一起显示就迁移所有引用、合并身份；或读取 B 却只绑定 A 的版本。
非 current Cue 只要依赖有效，可以成为未来产物的内容。当前 Presentation 不因此自动具备此能力。触发策略、格式版本、保存和失效实现待定，无伪 schema、provider 或绿灯测试。

## source-semantic-review
后台补认重新检查原讲授已经提供的证据。原文说了“只有 Y 成立时”，但当前 Cue 未保留它：这是根据原文补认的候选。原文没有 Y，外部参考建议补 Y：这是 ENRICH 新增备课参考，不能写成过去讲过。
理由：系统梳理可能遗漏，纠正解释应保留新接受时间及原历史。未来语义提案必须通过唯一接受入口，按 operation type 的来源、read/write scope、策略和版本资格启用。LLM 结果不必全由 Jev 逐项批准，也不能直接改写状态。
正例：有源地补认明确纠正或被批评例子的角色，并追加版本。反例：倒填首次讲述的条件；用外部标准答案无声覆盖教师原话；收藏一条增强建议就提交历史修订。
原 Cue 离开 Display 不等于内容失效。这个设计与旧 Presentation 仍限制 current 是两件事。当前未启用通用后台语义写入；门槛、保存审阅流程与各操作资格均待验证。

## retrieval-assistance
检索辅助的模型责任是条件式的：别名／派生摘要帮助找到来源；必要时 LLM 改写自由查询；对齐仅提出候选。基础本课 lookup、来源权限和 ID 分配是确定性代码，不改成模型职责。
正例：摘要命中后带回原文、限定与版本，供判断。反例：因为命中先修知识就声称老师已经教过；把检索分数当真伪权威；模型编造一条资产版本。
Recognition 在语义决定前扩展候选，Enrichment 在成立、实质修订或请求后找补充材料；普通 mention 不要求昂贵重查。自由查询、Pack 读取与模型选择未接入，条件式允许不等于强制流水线。

## cue-enrich
ENRICH 可以新增讲授没有的新例子、类比、批注或教学参考。结果要明确是补充与参考，绑定实际读取的来源和目标 Cue 版本，不冒充教师说过的话。
正例：围绕 A 给一个新例子，注明条件和来源，教师保存到备课笔记。反例：把新例子混进 TRACE 原文；编造页码／网址；收藏后给旧课堂新增 CREATE。
Presentation 只忠实表达既有内容，ENRICH 可扩展；两者不能共用一个含糊的权限标签。产物需要版本失效、删除、迟到结果隔离与作者修改保护；当前没有后端，UI 的请求入口不是能力完成证据。模型、指令、schema、触发细节待定。

## lesson-rework
REWORK 在明确范围的讲授记录上提出课序、转接和组织备选及取舍。它可直接读取整课，不要求先增强每个 Cue；不能只拿最后一个 current Cue 当整课。
正例：原顺序 A→B→补 A 条件保持不变，另存“先把条件与 A 放一起再讲 B”的草稿，并说明损失了原先探究顺序的可能价值。反例：修改 AcceptedEvent 顺序、自动合并 Cue、给教师总分或宣布唯一正确课序。
新回指和后续来源也可能改变结构，整课依赖应绑定范围／事件快照，不能只核对正文版本。界面范围入口已存在不代表请求后端、快照与持久产物已实现；这些均待定。

## review-only
身份拆分／合并建议和外部学科核查只能作为审阅意见。教师可能讲错，但原话与后续核查必须分别可见。
正例：保留“原讲授认为 X”并另附有依据的外部纠错意见。反例：后台把 X 改成 Y 并迁移历史引用，仿佛当时讲的就是 Y。
自动身份重组不在本轮范围；没有对应 prompt、schema 或 evaluator。审阅采纳流程、权限和迁移设计待定，不把已定义边界当开发排期。

## trace-narration
基础 TRACE 是对 AcceptedEvent、Cue 版本、来源和关系的确定性投影。无需模型就应能查看“讲了什么、怎么讲的”。可选命名、归纳或叙述若采用模型，必须另存带来源的派生产物。
正例：可选一段叙述帮助定位已有记录，同时可回到原 Cue。反例：叙述掩盖未捕获板书、把相邻事件编成因果、替代原始事件。当前没有接入，也不制造必做的 TraceSummary 服务。

## legacy-selection
structured-v3 保留旧单显示 Cue 判断，指令含 currentDescription、latestPath 和动态候选索引。手册直接读取原 buildJevRequest 的代码与具名人工请求预览，不复制指令到另一份规范。
scripts/replay.ts 的 Jev 模式及 /api/jev/decide 仍可达；产品原生路径走 /api/jev/inspect。旧 QUIET／UPDATE_CURRENT 不是后台语义补认，不把旧阅读规则升级为教师工作台产品规则。仅保留既有工具用途与测试，本轮未运行其付费模式。

## speech-recognition
Speechmatics 是相邻供应商能力。识别配置在 gateway；其内部识别指令不在仓库，不能编造。Final 作为稳定来源仍可能识别不准或语义不完整，partial 不授权 Cue。
正例：保留识别来源、角色未知和缺口。反例：凭说话人编号推定教师，凭 ASR 置信授予改写权限。Voice 模拟测试验证工程适配，不证明真实课堂识别效果。
